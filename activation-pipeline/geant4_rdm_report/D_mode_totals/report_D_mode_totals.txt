RadioactiveDecay6.1.2 and 6.1.3: decay-mode fractions that ignore the ENSDF
branchings (Pu233 decays by alpha only, Np231 alpha 95%, Bi212[239] has no
alpha branch, Tb157 feeds the wrong level)
==============================================================================

- Component: data library RadioactiveDecay6.1.2 and 6.1.3 (read by
  G4VRadioactiveDecay::LoadDecayTable)
- Geant4 version: 11.4.1 (datasets RadioactiveDecay6.1.2, G4ENSDFSTATE3.0,
  PhotonEvaporation6.1.2)
- Platform: macOS 15.8, Apple silicon (arm64)
- Severity: physics results are wrong, and no warning is printed

This is one of the related reports on the RadioactiveDecay6.1.2 and 6.1.3 data
(see "Related reports" at the end). The problem is the same in
RadioactiveDecay6.1.3d (provided after bug 2794): the mode fractions of the
levels below are unchanged.

Summary
-------

Each level in a RadioactiveDecay file has one summary line per decay mode (the
fraction of decays in that mode) and detail lines (the daughter levels of each
mode, with intensities in %). LoadDecayTable rescales the detail lines of each
mode so that they add up to the summary fraction. Only the summary lines
therefore decide how often each mode occurs.

In ENSDF, the decay-mode branchings of a level (for example %eps and %alpha)
and the feeding of individual daughter levels are separate data. The
branchings are totals, often measured directly. The feeding of a daughter
level is known only where the decays to that level have been observed, through
their gamma rays or alpha lines. For many nuclides, especially short-lived
ones, only part of a mode's decays, or none of them, can be assigned to
definite daughter levels in this way. The detail lines of the RadioactiveDecay
files contain only these assigned feedings, so for such a mode they add up to
less than its branching.

In some levels the summary fractions are not the ENSDF branchings. They are
the sum of the detail intensities of each mode, divided by the sum over all
modes. So a mode whose decays are only partly assigned to daughter levels gets
too few decays, a mode with no assigned decays disappears, and the other modes
are inflated. For example:

- Pu233 (ENSDF: eps 99.88%, alpha 0.12%). None of the eps decays is assigned
  to a daughter level, so the file has no eps line at all, and the alpha
  branch, with 0.12% in its detail line, becomes 100% of the decays.
- Np231 (ENSDF: eps ~ 98%, alpha ~ 2%). Detail lines: alpha 2%, beta+ 0.109%.
  Summary: alpha 2 / 2.109 = 0.948, beta+ 0.052.

A script finds 21 candidate levels with T1/2 >= 1 s. I compared each of them
with the ENSDF adopted levels in NuDat 3 (see the table): 17 have mode
fractions that disagree with ENSDF (two of them, Ho152 and No255, by
2-3sigma), one feeds the wrong daughter level (Tb157), and three are
consistent with ENSDF or have no ENSDF branching to compare with. Five of the
candidates have Z > 100; by default Geant4 does not decay them
(G4NucleusLimits: Z <= 100, A <= 260), so they matter only if the limits are
raised.

The modes of Bi212[239] are correct in a second record, at 250.7 keV with T1/2
= 0. LoadDecayTable matches the ENSDFSTATE level at 239 keV to the first
record, so this level always decays by beta-.

Tb157 is a different case: the mode is right (EC 100%), but the ground-state
feeding has intensity 1e-25, so after rescaling every decay goes to
Gd157[54.536]. In ENSDF this level gets only 0.11% of the decays (Igamma(54.5
keV) = 0.0084%):

    z65.a157 (Tb157)
    P            0  -  2.24059e+09
                                   MshellEC            0               1
                                   MshellEC            0  -        1e-25           60
                                   MshellEC       54.536  -         0.11        5.464

Only M-shell capture is listed; capture to the ground state (Q = 60 keV) is
also possible from the K and L shells.

How to reproduce
----------------

    source <geant4-install>/bin/geant4.sh
    python3 check_D_mode_totals.py [RadioactiveDecay dir]   # default: RadioactiveDecay6.1.2 in $GEANT4_DATA_DIR
    cd <rdecay01 build dir>
    ./rdecay01 rdecay01_D_mode_totals.mac                   # set G4RADIOACTIVEDATA to choose the library

The script lists the levels (1 s <= T1/2 < 10^15 s) where a mode gets more
than 50% of the decays although its detail lines add up to less than 50%, or
where a mode with 1% or more in its detail lines has no summary line. It is a
heuristic: it does not read ENSDF branchings, so levels with similar errors
can be missed.

Attached:
- check_D_mode_totals.py: standard-library Python script that lists the
  candidates;
- check_D_mode_totals.out, check_D_mode_totals_6.1.3d.out: its output for
  6.1.2 and 6.1.3d (same 21 levels);
- rdecay01_D_mode_totals.mac: macro for the unmodified example
  extended/radioactivedecay/rdecay01.

Possible fixes
--------------

- Take the summary fractions from the ENSDF decay-mode branchings (the %
  values of the adopted level), not from the sums of the daughter-level
  feedings.
- When none of a mode's decays is assigned to a daughter level (for example
  the eps branch of Pu233), keep its summary line, with the decay going to the
  daughter ground state.
- In the data generator, check that each summary fraction agrees with the
  ENSDF branching within its uncertainty, and that the ground-state feeding is
  not replaced by a placeholder intensity (Tb157).
